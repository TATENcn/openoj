# 范围与非目标

## Phase 0

Phase 0 建立项目宪法、稳定术语、需求与验收、架构与威胁模型、开发流程、Skills、协作模板和文档门禁。它不交付可运行判题系统。

## P0 产品范围

P0 实现一个算法题单机垂直切片：

- 创建版本化题目、测试数据、运行时和评测请求。
- 可靠调度到本机 judge node。
- 在 Firecracker microVM 内编译和运行少量受支持语言。
- 执行批处理测试、标准输出检查和结构化计分。
- 限制 CPU、内存、墙钟时间、进程、磁盘、I/O 和输出。
- 保存结构化结果、证据摘要、环境版本和审计事件。
- 对失败、取消、节点异常和强制回收提供确定行为。
- 提供最小 Web/API 操作路径和可观测性。

## P0 非目标

- 完整竞赛、排行榜、反作弊和社交系统。
- 大规模语言与框架矩阵。
- 复杂企业 IAM、多组织结算和商业市场。
- 通用中学考试、多模态阅卷和工程项目产品化。
- AI 自动做出不可复核的最终裁决。
- Kubernetes、跨区域高可用或无限水平扩展承诺。
- 不受限制的插件权限或宿主原生动态库。

这些能力可以保留协议扩展点，但不得为了假设的未来需求破坏 P0 的安全、正确性和可交付性。

## 自研边界

OpenOJ 自研领域模型、控制平面、评测编排、judge node、guest agent、协议、插件宿主、SDK 和产品界面。数据库、虚拟化、密码学、通用 Web 框架、对象存储协议和可观测标准使用成熟实现，并通过内部边界封装。
