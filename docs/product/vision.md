# 产品愿景

OpenOJ 是面向不可信工作负载的开放评测基础设施，而不只是传统算法竞赛网站。

项目使用 Rust 自研核心领域系统和判题控制链路，使用 Firecracker microVM 建立执行隔离，以算法题作为第一个完整、可验证的评测 Profile。在此基础上，OpenOJ 逐步支持文档、图片、音频、工程仓库和其他产物的通用评测，并允许确定性程序、受控插件、人工步骤和经过授权的 AI Agent 参与评测工作流。

## 目标

- 提供安全、可复现、可审计的不可信代码编译和执行能力。
- 提供开放、传输无关、可版本化的评测协议。
- 将评测表达为由输入、环境、阶段、证据和结果组成的工作流。
- 允许开发者通过能力受限的插件和稳定 SDK 扩展，而不修改核心系统。
- 支持从单机自托管到分布式 judge node 的渐进部署。
- 为 AI 提供强类型、最小权限、可审计的工具接口。
- 保持核心架构与未来身份、商业和外部平台集成解耦。

## 成功标准

成功不以“支持多少语言”或“页面数量”衡量，而以以下能力衡量：

- 一个结果能够解释其输入、题目、协议、运行时、执行环境、阶段和证据来源。
- 恶意工作负载超时、耗尽资源或崩溃时，宿主、其他任务和控制平面保持可用。
- 第三方可以只依赖公开协议和 SDK 实现兼容 evaluator、插件或客户端。
- 平台可以替换模型提供商、存储和基础设施，而不改写领域核心。
